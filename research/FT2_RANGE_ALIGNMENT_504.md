# 全载具射程核查 · 5.0.4

来源：本机 ft2 目录/原版分析。只读取原客户端 MyScripts.dll.bytes 与 Character.txt；角色编号沿用已核实的13台载具映射，未采用复刻项目规则。证据与原件SHA256见 FT2_ALL_RANGE_EVIDENCE.json，可运行 `uv run --with dnfile --with dncil python scripts/audit-range-model.py` 重建。

原表 Range 是蓄力上限，不是伤害Power。InitData写TotalRange，AnimationCallback传CurrentRange到CFightManage.Bullet，再用cos/sin×CurrentRange、整数截断、×100产生初速。核查普通／特殊28个分支（包括本作未采用的第14角色），各分支垂直加速度均100。能量弹没有本作过去的0.52倍重力；齐射、螺旋偏移、制导、卫星子弹等属于另行处理的行为。

5.0.4使用同一个尺度：老土在重力230、100%力度时保留730初速；各车两种武器初速为 `730 × Range/43 × 力度/100 × sqrt(地图重力/230)`，载具弹体重力倍率统一为1。这样保留当前地图重力与时间表现，同时无风、同高、同射角的抛物线射程都与原始连续包络成同一个固定比例。工厂与冰封溪谷52项实测初始化数据及比例在 QA/v5.0.4-launch-ranges.json。

比例基准为 `730²/(43²×230×3)`（原版网格到逻辑坐标×3）。本作使用连续速度以保留细力度操作，不复制原版向整数速度格截断造成的阶梯；不是逐帧、逐像素轨迹迁移。无风理论45°用于横向比对，有些坦克射界并不包含平地45°；实战还受坡度、风、地形、机体和追踪影响。

从1%到100%的载具力度改为原始线性比例。AI搜索下限也从10%扩展到1%，避免近距离仍用旧的力度区间；预测、真实发射、普通／特殊弹共用计算。各载具近射、AI自疗／队友治疗、真实落点与只读预测分别验证。额外空投武器维持原先曲线和特殊重力；恢复／转移装填沿用其炮弹载体。5.0.3与更早录像保留旧曲线、载具倍率和重力。

流星／暴龙齐射保留此前按用户体感验证的百分比分布；不重引入已确认有体感冲突的原始固定初速偏移。伤害、挖土Round、弹体外观、强化星星、双发、火线及制导规则不随本次射程修正改变。

## 同版交互与地图

头像允许在原高度重叠，不进行相邻避让；当前行动者最后绘制、命中检测优先匹配上层头像。开场巡展使用当前巡展角色；5.0.3及此前使用上一版兼容布局。屏幕边缘仍限制装饰溢出。

尸体在出界前仍保留60×51 AABB并随下落移动。各碰撞型武器都会在此截停，友伤关闭也不忽略尸体；尸体不会再受伤、治疗、复活或成为追踪目标。原有闪灵卫星子弹地面判定按用户确认保留，卫星定位弹仍正常碰撞。挖土仍是实际爆点与地形的完整椭圆相交；不重新加入正中减坑规则。小红豆在尸体头顶引爆不再穿到地面挖深坑，整数扫描线最多只切到地表边缘。

退出确认、图鉴、战绩、录像、更新和人物弹框沿用当前BGM时间线；专属选坦克音乐允许接管，关闭后恢复背景曲原位置。真实暂停和切到后台仍暂停音频。

蓄力准备改30ms，继续由大横条表现力度；200ms只用于区分横条轻点标记与释放发射。横条30ms开始预蓄力，短按释放撤回预蓄力并落标记，全局松手监听让此手势自己决定，防止先误发射。旧录像的200／100ms准备保持。

冰封溪谷按用户2026-11-18实机截图自绘左右交错冰带：左带向右下延伸至67%宽处，右带从41%宽处向右上延伸；中段留出真实垂直空隙。主体58px，两端收尖，独立下层S枝4px；出生、预览、小地图和破坏共用同一地形。截图仅作比例参考，不称逐像素复刻；之前录像保持原单带布局。名字、实际地图BGM候选不变。

普通坠落原本没有速度上限，因此坦克／尸体／转移降落伞的实际下落位移加快15%；箱子终速250→300（20%）。重力、落差伤害计算和免摔伤规则不变。箱子实时积分、落点预测与起点反推共用新终速，原有镜头观察和落地停留保持。新参数记录到快照，旧录像按原速度。

老兵的基础瞄准误差由75小调至70，失误概率、首炮／受地形扰动的校准惩罚、四档上限不变；新参数从5.0.4生效并进入校准日志。AI测试场景默认明确使用package版本，避免把开发标识下的旧追踪算法误当成发布验证。实际5.0.4的960行动首炮数据见QA/v5.0.4-ai-first-actions.json；单次固定样本不宣称总体命中率等于难度上限。发射者活着时仍忽略自己的碰撞体积；死亡后其尸体作为地图占位物参与碰撞。
