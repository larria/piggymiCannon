# 蓄力射程与追踪核查 · 5.0.3

来源：本机 ft2 目录/原版分析。只读取原客户端 `MyScripts.dll.bytes` 与 `resources/config/decrypted/Character.txt`，未使用复刻项目规则。指令证据在 `FT2_CHARGE_HOMING_EVIDENCE.json`；可用 `uv run --with dnfile --with dncil python scripts/audit-charge-homing.py` 重建。

## 公爵射程

`CCharacter.InitData` 的006a–006f把角色表Range写到TotalRange；`AnimationCallback` 的00f9把CurrentRange传入CFightManage.Bullet。该方法000c–003a用cos/sin×CurrentRange并转整数生成速度，完全不读取A1/A2Power。注意原指令是整数截断，参考手册写成round不准确。

已核实角色5为公爵：Range49、角度0–40；角色3老土Range43、角度25–45。角色1大腕45、叉叉47、甲壳虫47、水鬼47等均高于43；该表的普通13台中老土Range最低。公爵并非表中最高，远程体感还受射界、坡度与风影响。公爵两种弹分别创建CAmorN／CAmorS，但初速与重力相同，没有找到弹簧蓄力、毒气减速或额外射程倍率。

5.0.2满力初速730×1.02=744.6。无风／无坡／起落同高的理论射程20°约1550、40°约2374，地图宽2688；原生坡度、炮口高度和风会改变实际落点。浏览器实测蓄满确实提交100，没有发现上限失效。问题是本作沿用的通用速度倍率没有保留49与43的相对差异。

5.0.3只把公爵速度倍率改成49/43，以本作现有老土曲线作基准：满力831.86，同条件20°约1934、40°约2963，比老土约长30%。普通／特殊弹同步，AI／预测同源；1–9%接触短射及旧录像保持。其余坦克、重力、地图规格、伤害和挖土不变。这是恢复原表相对比例，未宣称完整迁移原版定点时间系统。无风理论值和不同出生点／坡度验证见 `QA/duke-charge-range.json`，不能把理论射程当成逆风或高低地形下的保证。

## 追踪

CHiddS（暴龙特殊）、CMissS（飞火特殊）的CheckNearPlayer完全相同：

- 0023–005e用 `(pos + posp×10)/100` 得到预计前进十步的位置；0060起遍历角色，选该预计位置150格半径内的最近点。150²来自Turning.Jyudo；本作每格3单位，因此半径450。
- ProcessElement只在下降、尚未锁定且已允许索敌时执行。003e–0079把速度直接改为 `(Dest−当前位置)×10`；若速度分量绝对值和不足700，则改乘20。
- 00e6–0100清零两个加速度分量并置HommingCheck。后续沿锁定时的目标位置直飞，不持续圆弧转向。原代码没有当前版本的“距脚下地面130以内”条件。

本作5.0.3以 `sqrt(3/当前重力)` 换算源tick，保留源整数网格探测和一次速度重设，锁定后不再受风／重力偏转。仍检查真实地形和机体，不穿墙，不扩大受击体积，不加伤害。目标点对应机体脚部；保留当前齐射初速分布及微小落点偏移。原客户端枚举逻辑未做本作的伤害开关筛选，接入时保留本作只对可伤害存活目标索敌、猎星仅索敌、目标倒地时清除黄金导弹整组的既有规则。这些约束属于本作兼容处理。

猎星是本作空投武器，没有宣称它在原客户端存在；复用上述制导。AI模型同步探测、速度与无加速度飞行，不只改视觉。

用户埃及快照第23行动：83号一枚擦中，其余84–91落地，未发生任何projectile-lock。复用九枚初速与最终可恢复地形后，5.0.3九枚锁定、七枚机体接触（含最后91号），两枚仍被地形阻挡。快照截断602条，最终地形已经受后续攻击影响，不能把该对照宣称为整局逐帧倒放；见 `QA/homing-egypt-comparison.json`。锁定时目标位置固定，移动／掉落或阻挡仍可能导致未命中，不做全部必中承诺。
