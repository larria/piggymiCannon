## clash 可借鉴的内容与真实问题

只读检查 `/Users/larkin_1/Downloads/dlModel/clash`，其 HEAD 为 `958e344`。主要依据 `src/render/pixilayer.js`、`src/render/renderer.js`、`src/main.js`、`docs/DEV.md`、`docs/LOG.md`。

| 发现 | 本项目处理 |
| --- | --- |
| Pixi 底层渲染静态战场/单位，Canvas 上层保留效果、状态、HUD | 可以逐层迁移，先减少静态绘制与粒子路径，再处理角色。短期过渡两层要测合成开销，不能凭层数推断省电。 |
| 原 Canvas 自绘路径预烘焙纹理，按 uid 复用 Sprite | 保留本作配色/几何，分离纹理生成与每帧变换；跨局复用 GPU 上下文与公共纹理。 |
| `docs/LOG.md` 的 v0.6.1 明确记录迁移后战场全黑 | `buildArenaCache()` 未返回 Canvas，产生 0×0 纹理；此前只看 PNG 字节量的测试漏检。必须验证尺寸、非透明像素、颜色及真正使用的后端。 |
| v0.6.0 遇到 `Texture.from(canvas)`、`baseTexture` API 差异、塔尺寸错误、模块缓存误诊 | 使用本版本类型检查与 `Texture({source:new CanvasSource(...)})`，避免复制旧调用；检测真实构建内容及纹理尺度。 |
| 声称不用 ticker，但 `app.init()` 没有显式 `autoStart:false` / `sharedTicker:false`，也未 `app.stop()` | 新入口显式关闭自动 ticker，再由唯一 RAF 驱动。初始化后自动计时器处于停止状态纳入测试。 |
| 触屏低端档关闭 shadowBlur，场景约 33fps | 不照搬。这次用户要求画面与声音不降级；不能以低帧率或删除效果证明性能改善。 |
| 日志报告 44 单位时约 0.36ms/帧，较旧版约降 60% | 是该项目开发记录，不能当成本作性能或功耗的测量值。本作最多4位坦克，其收益分布不同。 |

因此，clash 并不是“迁移中没有出现 bug”的样板。应借鉴它的缓存思路与已暴露的失败路径。

## 本作现状与优先级

`main.ts` 的 RAF 每次调用 `game.update()`、`renderer.draw()`、`dashboard.draw()`；只有 DOM `updateUI()` 约80ms节流。暂停时游戏时间冻结，但两个 Canvas 仍整帧绘制。主 Canvas 使用世界宽1280、DPR上限2，1194×834横屏下需要提交约2560宽的像素。下面是代码检查结论，实测数值另见 QA。

| 环节 | 当前状态 | 3.0 实施方向 |
| --- | --- | --- |
| 背景 | 已缓存纸纹、远景、云与地图背景 | 上传一次；相机只改容器变换，避免把完整最终画面每帧当纹理上传。 |
| 地形 | 依 revision 缓存像素占据；变化时重算整幅 ImageData。草边/草丛/经典细节仍逐帧画 | 把静态装饰也纳入缓存；先上传整图只在revision变化时更新，再评估脏块。逻辑碰撞仍用原 `mask/protectedMask`。 |
| 活体与倒地后的身体 | 每帧重复创建 Path2D、渐变、绘制车身/炮管/角色/头像/状态 | 车身与炮管分别纹理化，车身坡度、朝向、相对角/绝对角、后坐力按原变换顺序组合；角色与状态保留原连续动画直到等效迁移通过。不能用低帧精灵图代替动作。 |
| 粒子/弹体/尾迹 | 每粒子路径绘制；现代弱尾迹、强化星星有独立规则 | 对象池+批量 Sprite/纹理；相同形状缓存；保持粒子数量、时间、颜色和尾迹规则。追踪逻辑留在 Game。 |
| 仪表盘/小地图 | 地形底图已缓存，但仪表盘及人物标记每帧绘制 | 由角度/坡度/朝向/当前角色/视窗/地形revision等脏标记更新；蓄力条独立逐帧transform，保持触屏流畅。 |
| 暂停/设置/后台 | 暂停场景继续提交相同画面 | 冻结且相机停止后按需呈现；恢复时重置RAF时间差，不能补算隐藏时段/发出额外炮弹。大厅有呼吸动画时保持连续。 |
| 音频 | 短采样按需解码+缓存；BGM用HTMLAudio完整曲播放；切场景有相等检查 | 不把9首完整曲解码成常驻PCM；复用短音效、封顶并发、跨局释放活动source。保持解锁、开关、音量、暂停、离线Range。 |

Chrome基线还捕捉到一次王牌求解的72.7ms峰值。换渲染后端无法消除这类逻辑长帧；后续可评估保持同一候选顺序/随机序列的分步求解或Worker，把取消/旧回合结果/日志一致性加入回归。不能为了减少峰值改变AI精度或重新平衡难度。

## 独立验证入口

- `tools/pixi3-lab/`：原 `paintVehicle` 路径生成13张DPR2纹理，Pixi手动渲染。只验证静态载具烘焙，不代表全游戏已经迁移；炮管角度固定45°、时间固定0。原画面角色/特效没有用这个验证代替。
- 比较 Canvas直绘、缓存Canvas、Pixi Sprite三条路径，4个实例为本作数量上限，100个为合成压力。样本固定120次RAF提交；结果是CPU提交时间，**不等于GPU时长或发热/电量**。
- Pixel ImageData是straight alpha，WebGL extract是premultiplied alpha。首次比较错误地混用两者，边缘RGB有假差异。已统一到premultiplied RGBA再逐像素比较，阈值为每通道≤2，不能通过放宽平均值隐藏黑边。
- 13张320×320 RGBA原图约5.32MB，保留CPU源与GPU副本至少约10.65MB；这还不是全局内存预算。正式迁移应裁透明边、按部件/公共帧复用，避免把13载具×4角色×全部状态×角度组合烘焙成巨型图集；纹理存活与PCM内存需要独立测量，JS heap不能代表总内存。
- 测试覆盖非空/非透明纹理、自动ticker停止、缓存不逐帧上传、重复destroy安全、丢失上下文期间停止提交；另用真实 `WEBGL_lose_context` 验证恢复与13纹理重传。若某设备不提供扩展须明确记为skip。
- **正式入口后端回退尚未实现**，独立probe初始化失败会明确报错；不能把实验入口成功当成Safari/PWA生产回退已经通过。

## 实施顺序与发布门禁

1. 本轮先完成基线与probe，保留v2.3.10已发布tag。
2. 建立兼容原 `setGame/resize/focusAt/follow/draw`、视窗偏移属性的渲染接口与可选后端。Game与日志是唯一模拟来源；Pixi不能决定射击/伤害/倒地/轮转。新画布必须在旧画布完整显示时异步初始化，成功验证后再原子切换，初始化失败不留下黑屏。
3. 先静态背景/地形，再自绘车身/炮管、粒子/弹体，再细节；每一层保持对照模式。双Canvas过渡只是验证办法，最终保留与否要看CPU+GPU合成实测。
4. 优化暂停与仪表盘脏更新；全局保持一个RAF。120Hz屏幕上的输入/蓄力与视觉响应单独测，不在迁移时顺便换物理步进，避免改变命中/双发0.75秒/天气和快照重放。
5. 通过216项机制及相关Chrome/WebKit用例；六图、多坡度、四角色、13载具、26武器、所有状态/道具/倒地后的身体/齐射/双发/天气与音频逐项比较。截图一次只看一张，结论立即文字存档。
6. 1194×834与1210×834、实际iPad Pro的持续对局/输入/蓄力、前后台/旋转/上下文丢失/重开与PWA升级离线回归。至少30分钟压力与反复50次新局，检验纹理/source/context不持续增长。
7. 同场景同种子、相同分辨率、相同音量和特效数，至少3次暖机后配对测量；目标是主线程渲染+仪表盘p95下降≥30%，同时不得提高GPU持续负载/长帧、不得降低清晰度/动画节奏。此为**门禁目标，尚未达成结论**。真实能耗需设备能耗工具与温度/电量测试；桌面headless模拟不能证明省电。
8. 产物与PWA≤90,000,000字节；全部BGM完整不剪切，离线曲尾/循环/206 Range通过；三处原素材与`.workbuddy/`继续忽略。3.x后备素材本轮未接入。
9. 上述门禁完成后才单独提升3.0.0、CHANGELOG、提交、部署和验证；准备提交与大版本发布分开。
