# 3.x 后备素材与发布体积约束

## 当前状态

v2.3.6 已发布并推送回退 tag。本轮新增源素材仅留本机备用，不接入当前运行时，不提交 GitHub 或 Pages。现有 `.gitignore` 已覆盖 `.workbuddy/`、`assets/ft2-audio/`、`assets/ft2-bullets/` 和 `assets/ft2-extra/`；本次核对没有遗漏或待提交的忽略规则修改。

按用户提供清单，ft2-extra含121文件、约146M，包括tank原图与i16元数据、Spine、宠物／旗帜、道具、位图字体、原客户端解密配置、选定GUI与logo。音频249M、炮弹／特效51M和本批146M均为本机来源原件，不进入发布产物。未搬地图281M／Unity原始数据1.4G，不为准备阶段补下载。来源是用户本机ft2逆向提取，仅本项目使用，未宣称官方授权。

## 进入3.x后

- 先确认用户指定pixel.js的具体库；保留v2.3.6回退节点，3.0.0代码与前版分开提交／发布。
- 再按实际表现收益选择少量素材，先估算运行时与解码内存，再压缩／裁剪／转码；未采用的继续忽略。此时才决定哪些处理后的文件值得提交，优先放入明确的运行时目录，不整包解除忽略。
- 原图／元数据可用于形态、颜色、动画、文案核对；i16／bytes需专门解码。原客户端的可确证资料与本作推断分别标注。supertank-web的规则不作依据，原配置也不盲目覆盖已验证的游戏机制。
- 画面与声音保持：13台自绘载具、原头像与独立人物动画、暖纸色、地形破坏／永久层、特效／尾迹、101段音频、独立开关／音量及PWA离线。性能基准另测帧耗时、CPU／GPU代理指标、内存和长局，不用压缩体积代替耗电测试结论。
- 图片每次仅查看1张，立刻保存文字核对结果，不拼图／批量查看。

## 硬上限

最终dist及PWA预缓存总量均≤90 MB；采用更严格的十进制90,000,000字节（约85.83MiB）。构建后记录du -sh dist、文件实际字节、磁盘分配字节与预缓存清单总量。解码／GPU内存另测。

`npm run check:size` 自动读取dist与生成的SW数据清单。`build`／`build:pages`／`predeploy`都会执行：dist逻辑与分配字节、保守包含重复项的缓存字节超限即失败；外部无法计量URL、缺失／越界文件、同URL版本冲突、来源／私有目录混入产物也失败。相同版本的重复条目分别报告原始清单与实际去重总量，不重复计算实际缓存。

测量可保存：`node scripts/check-release-size.mjs --report QA/<版本>-release-size.json`。以后每次3.x引入素材前后均需更新该数据与QA，当前基线见QA/v2.3.6-release-size.json。
